# 四级汉译英批改报告生成器

产出一张单文件 HTML（7 个标签页）：

| 标签 | 内容 |
|---|---|
| **总结** | 分数环、总评、简单版提示、一句话诊断 |
| **逐句批改** | 手写转录 + 逐句标注，点任意标注弹右侧详情面板 |
| **错误清单** | 表格，按类型筛选 |
| **两版对照** | 精确版 vs 简单版 + 逐条降级记录 |
| **评分解析** | 官方六档表 + 维度条形图 + 710 折算 |
| **保底打法** | 三招换词 + 拆句示例 + 考场五步走（方法论页） |
| **改写与提升** | 最小改动版对比 + 硬伤清单 + 搭配表 |

顶部两条 sticky 常驻：第一行 7 个标签 + 右侧统计，第二行**分类跳转 chips**（点「搭配 5」→ 直接滚到第一处搭配错并弹出详情，再点取消）。

**核心设计：AI 只写 `data.json`，HTML 由 `scripts/build.py` 渲染。** 不要手写 HTML——手写必然走样。

## 铁律

1. **不臆测字迹。** 看不清就裁图放大二次确认；一处模糊，宁可写"字迹不清"也不能猜。低清图上 `new/now`、`develop/development`、`enterprise/entre` 极易误判，误判比漏标更糟。
2. **错误必须落到具体 token 上。** 不能整句标红。一个 `<span class="mark">` 只包住真正出错的那几个词。
3. **评分按档位，不逐条扣分。** 官方是六档整体印象分，先判"进哪一档"，再在档内浮动。
4. **简单版必须零语法错误、信息点不丢。** 简单 ≠ 省略。宁可拆成三句，不可删信息。
5. **只改 JSON，不改模板。** 模板的 CSS/JS 已调好（sticky 头、上标掉行、长 span 换行、移动端抽屉都处理过）。

## 工作流

### Step 1｜定位题目

读图确认：考试年月、第几套、题型（Part IV 汉译英 15 分制）。
联网核对**官方中文原文**（逐句，不要凭记忆），记下分句。
> 例：2024.12 第 3 套「新能源汽车」共 4 句。

### Step 2｜转录（最易翻车的一步）

完整协议见 `references/transcription.md`，最低要求：

- 用 PIL 按行切割 + 2–4 倍放大 + 对比度 1.3–1.4，逐行识别
- **划改判定**：横线穿过文字 = 划掉；字母上方补写 = 插入。二者语义完全不同，搞反会凭空造出一个错误
- **交叉验证**：同一个词在别处出现过，比对两处写法；两处不一致才判拼写错
- 转录结果按**手写换行**保留，放进 `data.transcript`，划掉的部分用 `<del>`

### Step 3｜分句对齐

把译文按中文原文的句子切块（一般 3–5 块）。每块的 `tokens` 是**有序片段数组**：普通文字直接写 `{"t": "..."}`，需要标注的写 `{"t": "...", "e": "e1"}`，被划掉的写 `{"t": "...", "strike": true}`。

中文原句放 `zh`，官方译文放 `ref`。

### Step 4｜标错

五类，定义与判定见 `references/error-taxonomy.md`：

| type | 中文 | 典型 |
|---|---|---|
| `grammar` | 语法 | 主谓不一致、时态、冠词、句法残缺 |
| `spelling` | 拼写 | 单词拼错、词形错 |
| `collocation` | 搭配 | 中文硬翻、动词与名词不搭 |
| `word` | 用词 | 词义偏差、词性误用、语域不当 |
| `logic` | 逻辑/漏译 | 信息挂错主语、整块信息丢失 |

标注粒度：**一个错误一个编号，按出现顺序 e1、e2…连续递增**。
每条必须写全：`bad`（原写法）、`good`（改法）、`why`（讲清"为什么错"，2–5 句，可用 `<b>` 分段）、`src`（对应中文）、`srcEn`（对应英文）。

`why` 的写法：先点出错在哪，再给正确形式，最后给一句可迁移的规律。不要只写"应为 has developed"。

### Step 5｜打分

按 `references/rubric.md`：
1. 先数**严重错误**（结构级：谓语残缺、主谓不一致、词性误用、信息错位）
2. 定档：0 严重错误 → 11–14；1–3 处 + 较多小错 → 8；4 处以上或大面积不通 → 5
3. 档内浮动到 0.5 分精度
4. 折算：`710 分制 = 106.5 × 分数 ÷ 15`

必须同时填 `dims`（内容传达/语言准确/行文连贯/综合）和 `kv`（含折算值），页面靠它们画条形图。

### Step 6｜写简单版（本 skill 的特色）

**方法论见 `references/downgrade-method.md`**（三招换词 + 拆句 + 考场五步，源自 B 站四级急救课笔记）。

**逐句**产出 `simple` + `simpleNote`，目标是"零错误、初中词汇、11 分档"。三条降级路径按序用：

1. **上位词**：文化遗产 → old culture；旅游景点 → a place；高楼大厦 → many buildings
2. **解释出来**（七成情况靠这招）：京杭大运河 → the river from Beijing to Hangzhou
3. **大词硬写、小词删掉**：主干上的词不会就写个意思接近的；定语状语不会就装作没看见

长句一律拆成 2–3 个简单句，句间用 and / but / so / also。**不确定是真因果就别用 as a result。**

同时填 `downgrades` 数组，逐条记录"范文写法 → 降级写法 → 代价"，这是页面上最有教学价值的部分。

**验收**：把简单版单独拿出来读，如果出现任何一个你自己都要查词典的词，说明降级不够；如果少了一个信息点，说明降级过头。

### Step 7｜写 data.json

结构见 `references/data-format.md`。以 `assets/example-data.json` 为起点复制修改，不要从零写。

**`method` 字段整块复制示例数据的即可**，只把 `splits` 里的例句换成这篇真题的句子——那是「保底打法」页的内容，不填这一页会是空白的。

### Step 8｜构建 + 自检

```bash
python3 scripts/build.py data.json report.html --shot
```

`build.py` 会校验：字段完整性、编号连续性、token 引用的错误是否存在、有无重复引用、HTML 标签是否配对、档位与错误数是否矛盾、`method` 结构是否合法。**有 FAIL 必须修，不要绕过。**

然后打开截图看四处：
1. 分数环数字对不对
2. 顶栏 7 个标签是否放得下（1180px 宽下不该被切）
3. 分类 chips 行：点某类能否跳到对应错误并弹出详情
4. 手机宽度（390px）下有没有横向溢出、chips 换行是否完整

### Step 9｜交付

`present_files` 提交 HTML，正文里给：得分 + 档位 + 折算分、错误统计（分类计数）、最致命的 2–3 处、简单版能到多少分。

不要把 20 多条错误在聊天里全列一遍——那是 HTML 的活。

## 常见翻车点

- **低清图误判**：拿到第二张更清晰的图后要**重新逐行核**，不要沿用第一次的转录。曾因低清图把划掉的 `develop have` 当成正文、把 `development` 看成 `develop`，多标了两个错。
- **划改方向搞反**：学生划掉 A 改成 B，最终文本是 B。若只标 B 的错，别忘了在 `why` 里肯定"划掉 A 是对的"。
- **上标掉行**：长 span（>12 词）末尾的上标会被浏览器推到下一行。控制在 10 词以内，或用 `position:relative` 而非 `vertical-align:super`（模板已处理，但别把 span 拉太长）。
- **编号跳号**：删掉某条错误后忘记重排，页面上会出现 e23 而总数只有 21。
- **档位与错误数打架**：21 处错误给 11 分，或 3 处错误给 6 分，都会被 `build.py` 警告。
- **`method` 留空**：页面能生成，但「保底打法」标签页点进去是空白的，学生最需要的那个方法页没了。
- **简单版写成「省略版」**：把不会翻译的信息整块删掉，看似零错误，实则漏译——那是 5 分档的做法。
